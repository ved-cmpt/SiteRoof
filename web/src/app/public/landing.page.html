The approach

One system of record for day-to-day execution

  • Every work order belongs to a project, and only that project's team can be assigned to it.
  • Progress, blockers and approvals are stored once and audited, so the dashboard is always derived, never typed in.
  • Integration to purchasing is asynchronous and idempotent, so a flaky ERP never loses or duplicates an order.

Architecture and decisions Source

Tested against a real database

  • A crew member cannot view another project by changing a URL id.
  • Approvals are logged, idempotent and refused for crew accounts.
  • ERP returns 503 once; the retry succeeds with no duplicate requisition.
  • Conflicting edits return a visible 409 instead of overwriting.
  • Creating and completing work updates the dashboard, database and activity feed.

xUnit integration tests run the real API against SQL Server 2022 in a disposable container; Playwright drives the full recruiter scenario in a browser.

Why this exists

A portfolio project about the software behind building things

I built SiteRoof as an independent portfolio project while applying for a software developer student role at a general contractor in Edmonton. It is my attempt to show, with working code, the kind of internal business software construction teams depend on: secure web apps, clean APIs, careful relational data, reliable integrations and tests that check the business rules.

It is not affiliated with or endorsed by any company, and every project, person and record in it is fictional.
